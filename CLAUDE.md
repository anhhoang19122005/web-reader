# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Architecture

Novel Reader is a two-tier app: a Go backend (`go-api/`) and a Next.js 16 frontend (`web/`). An older Spring Boot `api/` directory still exists but is no longer the active backend — all work should target `go-api/`.

- **go-api/** — single Go module. Entry points: `cmd/local` (long-running local server on port 8081) and `cmd/migrate` (one-shot MongoDB index migration). All domain logic lives flat in the package (`books.go`, `reader.go`, `tts.go`, `piper.go`, `vieneu.go`, `storage.go`, `mongo.go`, `preferences.go`, etc.). TTS has four providers wired through the same handler: Edge-TTS (built into Go, no Python), SaydiVoice (rotates through `SAYDI_API_KEYS` on quota/auth/rate errors), Piper (local offline, loaded from `tools/piper/`), and VieNeu (local Python server at `test/VieNeu-TTS`).
- **web/** — Next.js 16 App Router with React 19, TanStack Query, Zustand, Tailwind v4. **This is NOT the Next.js in your training data** — read `web/node_modules/next/dist/docs/` before writing frontend code. `web/AGENTS.md` is auto-regenerated by `next dev`; don't hand-edit it, but do commit it when it changes alongside your work.
- **MongoDB Atlas** stores `books`, `chapters` (separated to avoid the 16 MiB BSON limit), `reading_progress`, `bookmarks`, `audio_chunks`, `reading_preferences`. Chapter audio is deduped and cached; TanStack Query holds URLs for 24h, player preloads up to 3 chunks ahead.
- **Storage**: `STORAGE_PROVIDER=local` for dev, `supabase` for deploy. The service-role key is backend-only; web uses the anon key with short-signed URLs issued by the API.
- **Deployment**: two Vercel projects from the same repo (root dirs `go-api` and `web`). Piper requires Docker (set `PIPER_ENABLED=false` on Vercel Functions). The personal path is `start-reader-home.ps1 -Publish` which runs the Go API locally and exposes it via Cloudflare Quick Tunnel.

## Commands

Scripts auto-install Go via `winget` and Python/edge-tts/piper as needed. All PowerShell scripts expect to run from the repo root in `pwsh` 7.4+.

```powershell
# Local dev: Go API (8081) + Next.js (3000) together
.\start-reader-go.ps1

# Personal deploy: local API + Cloudflare tunnel + Vercel redeploy
pwsh -File .\start-reader-home.ps1 -Publish
pwsh -File .\start-reader-home.ps1 -Restart -Publish   # after backend changes
```

Backend:
```powershell
cd go-api
go run ./cmd/local            # API at http://localhost:8081/api, health /api/health
go run ./cmd/migrate          # one-shot MongoDB index migration
go test ./...                 # unit tests
go vet ./...
READER_INTEGRATION_TEST=true go test ./...   # MongoDB integration tests on throwaway `rpt_<UUID>` DB
go test -run TestVieNeuLocalIntegration -v   # requires VIENEU_INTEGRATION_URL + running VieNeu server
```

Frontend (from `web/`):
```powershell
npm run dev       # port 3000
npm run build
npm run lint
```

Playwright UI checks (API mocked, service workers blocked):
```powershell
playwright-cli open about:blank
playwright-cli run-code --filename web/tests/reader-upgrades.js
```

PWA offline tests use a dedicated production fixture — see `web/AGENTS.md` for the three-terminal setup; never run them against the real API.

## Environment

Both PowerShell scripts read `.env` at the repo root. Required keys: `MONGODB_URI`, `MONGODB_DATABASE`, `NEXT_PUBLIC_API_BASE_URL`, `CORS_ALLOWED_ORIGINS` (must include `http://localhost:3000` locally). Optional provider keys: `EDGE_TTS_ENABLED`, `SAYDI_API_KEYS` (comma-separated; `SAYDI_API_KEY` is legacy single-key), `SAYDI_VOICE_ID`/`SAYDI_VOICE_NAME` (fallback only), `PIPER_ENABLED`, `VIENEU_API_URL`, `AZURE_SPEECH_KEY`/`AZURE_SPEECH_REGION`, `FPT_AI_API_KEY`, `READER_ACCESS_TOKEN` (only enforced on the tunnel-exposed API). `AUTO_MIGRATE=true` runs MongoDB index creation on every Go start.

## Conventions

- End the final response of each implementation with a **concise change summary in Vietnamese**: list every file added/modified/deleted with path + short explanation, plus validation performed (or explicitly state what was skipped).
- Reader progress uses UTF-16 `characterPosition`; preserve the existing schema. Backend keeps the furthest-read marker — don't let scroll restore / font changes / TTS auto-scroll overwrite it.
- Preferences PATCH is partial `$set` per field (never replace the document). Unknown fields are rejected. Web debounces 500 ms, queues `pending`, retries on reconnect/focus.
- Don't commit `.reader-deploy/credentials.json`, the VieNeu checkout, or Piper models.
