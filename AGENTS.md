# Novel Reader — Agent Ramp-Up Guide

## Runtime: Go API

- **Go API**: `cd go-api && go run ./cmd/local` — port 8081, health at `/api/health`. Auto-migrates if `AUTO_MIGRATE=true`.
- The Go API serves the `web/` Next.js frontend at `http://localhost:3000`. CORS must allow `http://localhost:3000` (local) or the Vercel domain (production).

## Docker & DB

- Go uses MongoDB Atlas. Set `MONGODB_URI` and `MONGODB_DATABASE` in the root `.env` before running `start-reader-go.ps1`.
- Migration creates MongoDB indexes automatically on Go startup (`AUTO_MIGRATE=true`). To run manually: `go run ./cmd/migrate` from `go-api/`.

## Environment

- `.env` at repo root is read by both PowerShell scripts. Key vars:
  - `MONGODB_URI`, `MONGODB_DATABASE`
  - `NEXT_PUBLIC_API_BASE_URL` (e.g. `http://localhost:8081/api`)
  - `CORS_ALLOWED_ORIGINS` (must include `http://localhost:3000`)
  - `STORAGE_PROVIDER` (`local` for dev, `supabase` for deploy)
  - `SUPABASE_URL`, `SUPABASE_SERVICE_ROLE_KEY`, `SUPABASE_STORAGE_BUCKET=reader`
  - `EDGE_TTS_ENABLED` (`true`/`false`)
  - `AZURE_SPEECH_KEY` / `AZURE_SPEECH_REGION`, `FPT_AI_API_KEY`, `SAYDI_API_KEY`
- Scripts also auto-install Go (`winget`) or Python/edge-tts as needed.

## Web (Next.js)

- `cd web && npm run dev` — port 3000, API proxied to whatever backend is running.
- `npm run build` for production. `npm run lint` for linting.
- **Never edit `web/AGENTS.md`** — it is auto-regenerated by `next dev` from `node_modules/next/dist/`. The block at the top covers breaking API changes in Next.js 16.x.

## Deploy (Vercel)

- Two projects from same GitHub repo:
  1. **API project**: Root Directory `go-api`. Set env vars: `MONGODB_URI`, `MONGODB_DATABASE`, `STORAGE_PROVIDER=supabase`, `SUPABASE_URL`, `SUPABASE_SERVICE_ROLE_KEY`, `SUPABASE_STORAGE_BUCKET=reader`, `EDGE_TTS_ENABLED=true`, `CORS_ALLOWED_ORIGINS=<web-url>`.
  2. **Web project**: Root Directory `web`. Set env vars: `NEXT_PUBLIC_API_BASE_URL=<api-url>`, `NEXT_PUBLIC_SUPABASE_URL`, `NEXT_PUBLIC_SUPABASE_ANON_KEY`.
- `SUPABASE_SERVICE_ROLE_KEY` goes **only** on the API project. Web uses the publishable/anon key for short-signed URL uploads.

## Testing

- Go: unit tests exist (`go test ./...` from `go-api/`)
- No CI config found; Atlas credentials are required for Go integration tests.

## What NOT to miss

- The `.env` file **must** exist and have correct values before starting anything.
- `AUTO_MIGRATE=true` on the Go backend will create MongoDB indexes on every start — disable if you want manual control.
- Edge-TTS in the Go backend is built-in; no Python pip install needed.
- CORS: if `CORS_ALLOWED_ORIGINS` is missing or wrong, the web will fail to call the API.
